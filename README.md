# Qommons IN

行政職員がつながり、知見を業務の型へ育てる共創プラットフォームの提案用MVPです。相談投稿 → 全国行政AXレポジトリ → QommonsAIで自庁との差分確認 → 改善案の共有を体験できます。

## 公開先・ログイン

[Vercelのログイン画面](https://qommonsin.vercel.app/login)

グラデーション背景とグラスモーフィズムのログイン画面を備え、指定アカウントをサーバーで認証します。資格情報はVercelの非公開環境変数で管理し、リポジトリやブラウザのコードには含めません。

GitHub Pagesではサーバー認証を実行できないため、公開先にはVercelを使用します。ルートのindex.htmlはVercelログインへの案内のみです。旧オフライン版は認証を持たないため、アクセス制限が必要な公開には使用しないでください。

GitHubリポジトリは現在Publicです。公開されるのはソースコードと架空のデモデータであり、認証情報や実データを追加しないでください。

## ローカル起動

Node.js 22以上（検証環境は24）とnpmが必要です。

```sh
npm ci
npm run configure:auth
npm run dev
```

設定スクリプトでメールアドレスとパスワードを入力します。パスワードは非表示で受け付け、scryptハッシュと署名鍵を.env.localに保存します。このファイルはGit管理対象外です。[http://127.0.0.1:3000](http://127.0.0.1:3000) を開いてログインします。

```sh
npm run build
npm start
```

## Vercelの設定

GitHubのmainをNext.jsプロジェクトとして接続し、Environment Variablesに以下をSecretとして登録します。Production環境が対象です。プレビューでも認証を使う場合はPreviewにも登録してください。

| キー                   | 内容                                     |
| ---------------------- | ---------------------------------------- |
| QOMMONS_LOGIN_EMAIL    | ログインを許可するメールアドレス         |
| QOMMONS_PASSWORD_HASH  | configure:authで生成したscryptハッシュ   |
| QOMMONS_SESSION_SECRET | configure:authで生成したランダムな署名鍵 |

これらにNEXT_PUBLIC_を付けないでください。.env.localのImportはVercelの非公開設定画面でのみ行い、GitHubへアップロードしないでください。設定が不足・不正な場合、アプリは認証を通しません。

- ログイン状態はjoseのHS256署名付きセッションで管理し、有効期限は8時間です。
- CookieはHttpOnly / SameSite=Lax / 本番ではSecureです。
- HTMLだけでなくJavaScript・画像への直接アクセスもproxy.tsで保護し、ホームのサーバー処理でも再確認します。
- ログインページは自己完結したHTMLで、nonce付きCSPを設定しています。
- ログイン・ログアウトは同一Originからの送信だけを受け付けます。
- 試行制限はインスタンス内で管理します。分散環境での厳密な制限、MFA、複数アカウント管理、パスワード再発行は含みません。
- [Next.js Proxyの公式仕様](https://nextjs.org/docs/app/api-reference/file-conventions/proxy)に従い、保護対象のアセットを除外しない構成です。

## 90秒のデモ

1. ホーム先頭の青葉市・田中 美咲さんによる給付金申請の不備確認の相談と、朝凪市・佐藤 健太さんのコメントを見る。
2. 「関連AXパッケージ：給付金申請受付・審査」を開く。
3. 承認状態、業務フロー、不備あり時の補正・再提出、6つの構成要素を確認。
4. 「この型を使ってみる」から、紙／オンライン、庁内／外部審査を選んで差分を確認。
5. 「改善案を投稿する」で下書きを確認し、コミュニティへ投稿。
6. プロフィールメニューからログアウト。

## 実装機能

- 深緑の3カラムフィード、固定ヘッダー、Polimillロゴ、自然な日本語、モバイル下部ナビゲーション。
- 架空の職員6名と公式アカウント、初期投稿10件、相談・事例・公式Tips・イベント。
- 投稿、2MB以下の画像添付・プレビュー、いいね、コメント、リポスト、引用、保存、フォロー、投稿・職員・部署・自治体検索。
- ネットワーク、プロフィール、保存済み項目、通知、コミュニティ・イベントのデモ操作。
- 6つのAXパッケージ、検索・分野・承認フィルター、個別業務フロー、構成要素、JSON/CSV等のサンプルダウンロード、関連投稿。
- シナリオAIによる差分確認・追加メモ・改善案への引き継ぎ。
- 投稿・コメント・反応・保存・フォロー・リポストをlocalStorageに保存。破損時は初期状態へ戻し、容量不足を通知。

## 検証

```sh
npm test
npm run typecheck
npm run build
npm run test:auth-http
npm run test:e2e
```

ロジック・認証・経路の21件のテストと、本番サーバーを実際のHTTPで確認する10項目の検証を備えています。実HTTPテストはテスト用資格情報だけを使用し、正しいログイン、Cookie属性、未認証アセット、ログアウト後の再アクセスを確認します。

ブラウザE2EはChromeを使い、1440×1000と390×844で動作を確認するコードです。ローカルでは3105番ポートに専用テストアカウントで開発サーバーを起動します。既存のサーバーや本番アカウントを変更しません。リモート環境を対象にする場合はBASE_URL・TEST_LOGIN_EMAIL・TEST_LOGIN_PASSWORDを安全な環境変数として指定してください。

## 構成

Next.js App Router / React 19 / TypeScript / Lucide / jose / CSS。バージョンはpackage-lock.jsonで固定。外部AI API・本番DB・APIキーは不要です。

- app/：ホームとログイン経路
- proxy.ts：未認証リクエストの保護
- lib/auth.ts：資格情報・セッション・試行制限
- lib/login-page.ts：ログイン画面
- components/：フィード、レポジトリ、プロフィール、AIデモ
- lib/data.ts・model.ts：架空データと操作ロジック
- scripts/：非公開認証設定の生成・実HTTP検証・旧オフライン版の生成
- tests/：認証・ロジック・出力形式・ブラウザシナリオ
- docs/REQUEST.md：ユーザー提供の指示書

## デモ上の前提

人物・自治体・数値・成果・承認状態・イベントはすべて架空です。SNSの投稿は未検証の知見として、責任者承認済みパッケージと区別しています。全国行政AXレポジトリは2027年4月公開予定の構想です。AIは定義済みシナリオで、自由入力を分析したり外部へ送信したりしません。

LGWAN、課金、監査、実業務の自動実行、複数ユーザー管理は対象外です。記載のPDFは今回添付されておらず、指示書にあるフローを実装しています。
