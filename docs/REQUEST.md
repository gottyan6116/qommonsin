# Qommons IN｜行政職員向け共創プラットフォーム — 超MVP開発指示書

## 1. ミッション

Polimill株式会社の新規事業構想「Qommons IN（仮称）」を、社長への提案に使用する**実際に操作可能な高品質Webアプリケーション**として開発してください。

GitHubリポジトリ：
https://github.com/gottyan6116/qommonsin

今回の目的は本番サービスの構築ではなく、**新規事業の可能性を経営陣に直感的に伝えること**です。

完成度の低いワイヤーフレームや静的なモックではなく、既存の商用SNSと遜色ないリアリティを持つ、インタラクティブな超MVPを目指してください。

### プロダクトコンセプト

**行政版LinkedIn × 全国行政AXレポジトリ × QommonsAI 3.0**

全国の自治体職員がつながり、実務上の課題や知見を共有。その交流から生まれた解決策を検証・標準化して全国行政AXレポジトリに蓄積し、QommonsAIを通じて他自治体でも再利用できるプラットフォーム。

目指す価値は次の3つです。

1. 自治体職員の交流・人的ネットワークの形成
2. 行政実務の課題解決・成功事例の共有
3. QommonsAIによる知識の検索・活用と業務改善の全国展開

**「課題を発見する → 知恵を共有する → 業務の型にする → 全国で再利用する → 改善を還元する」** という循環を実現します。

## 2. UI/UX：最重要要件

添付のLinkedInデスクトップ版スクリーンショットを、UIの第一参考資料としてください。

今回は特に**見た目のリアリティ、情報密度、余白、カード構成、操作感**を重視します。

### デザインの基本方針

- LinkedInのデスクトップ版フィード画面を強く参考にした情報設計
- 上部固定ヘッダーと3カラム構成
- 左：プロフィール・個人メニュー
- 中央：投稿コンポーザー・フィード
- 右：注目トピック・おすすめ・公式情報
- カードの幅、高さ、文字組み、アイコン、ボーダー、余白まで丁寧に調整
- 自然な日本語のUI
- 実際に職員が毎日使っていそうな情報量と投稿内容
- ホバー、クリック、選択状態、モーダルなどの自然なインタラクション
- 過剰なグラデーション、大きすぎるカード、無駄な余白、AI生成サイト特有の装飾を避ける

参考画面の画面構成や一般的なUIパターンは積極的に取り入れつつ、LinkedIn固有のロゴ・画像・ブランドアセット・ソースコードは複製しないでください。

### ロゴとブランド

**左上のLinkedInロゴに相当する場所には、添付のPolimill公式ロゴを配置してください。**

- 添付ロゴの形状・色・縦横比は維持
- ロゴが不自然に大きくならないようヘッダーに収める
- サービス名は「Qommons IN」
- LinkedInの青を使用せず、深緑を中心に独自のブランドを構築
- Polimillのオレンジ色のロゴと、UIの緑色は共存させる

### カラーパレット

- Primary：#176B52（Deep Green）
- Accent：#67C59F（Mint Green）
- Background：#F5F7F6
- Surface：#FFFFFF
- Border：#DDE5E0
- Main Text：#24362D
- Secondary Text：#5F6F67

画面全体を緑色に染めるのではなく、白とニュートラルカラーを主体とし、CTA・アクティブ状態・重要情報に緑を使用してください。

フォントはNoto Sans JPなど、自然で読みやすい日本語フォントを採用してください。

デスクトップでは1280〜1440px程度のブラウザ表示を主な評価対象とし、モバイルにも対応してください。

## 3. 実装する主要画面

### A. ホーム／SNSフィード（最優先）

LinkedInのようなリアルなSNS画面を構築してください。

**固定ヘッダー**
- Polimillロゴ
- Qommons IN
- 検索バー
- ホーム
- ネットワーク
- AXレポジトリ
- 通知
- プロフィール

アイコンとテキストを組み合わせた、コンパクトなナビゲーションを採用してください。

**左カラム**
- 職員プロフィールカード
- カバー画像とアバター
- 氏名・自治体・所属部署
- プロフィール閲覧
- 保存済み項目
- 参加コミュニティ
- イベント

**中央カラム**
- 投稿作成エリア

- いいね・コメント・リポスト・引用・保存

投稿カードにはプロフィール写真、氏名、部署、投稿時間、公開範囲、本文、画像、リアクション数、コメント数を適切に配置してください。

**右カラム**

- おすすめの職員・コミュニティ
- Polimill公式アカウント

- イベント・勉強会

重要なのは、**画面を開いた瞬間に、実在する行政職員向けSNSだと感じられること**です。

### B. 全国行政AXレポジトリ

添付PDF「全国行政AXレポジトリ_A4両面.pdf」を仕様・概念の参考資料として使用してください。

- 業務パッケージ一覧
- キーワード検索
- 行政分野別フィルター
- パッケージ詳細への遷移
- 業務フロー図

- 判断基準
- 成果物ひな形
- 検証用テスト
- 関連するSNS投稿

レポジトリを単なるファイル一覧ではなく、職員が必要な業務の型を探しやすいプロダクトとして表現してください。

### C. AXパッケージ詳細

メインのデモ対象は「給付金申請受付・審査」です。

添付資料にある以下のフローを視覚化してください。

申請書の提出 → 受付・添付確認 → 不備判定 → 必要に応じて補正・再提出 → 対象要件の確認 → 結果の通知

詳細画面に以下を設置します。

- パッケージ概要
- 業務フロー図
- 構成要素
- 検証・承認状態
- 関連するSNS投稿
- 「この型を使ってみる」
- 「QommonsAIに相談」
- 「改善案を共有」

**SNS上の未検証情報と、業務責任者が承認したAXパッケージを明確に区別してください。**

今回は本物のAI API接続は不要です。事前定義されたシナリオによってAI支援体験を再現してください。

デモであることは明示してください。

## 4. 社長へのデモシナリオ

**次の一連の動作を、90秒程度で体験できるようにしてください。**

1. ホームフィードに、A市の福祉課職員による「給付金申請書の不備確認に時間がかかっている」という投稿が表示される。
2. B市の職員がコメントで効率化事例を共有している。
3. 投稿に紐づく「関連AXパッケージ：給付金申請受付・審査」をクリックする。
4. 全国行政AXレポジトリのパッケージ詳細へ移動する。
5. 業務フローと構成要素を確認する。
6. 「この型を使ってみる」をクリックする。
7. QommonsAIが自庁との差分確認をサポートするデモが始まる。
8. 「改善案を共有する」をクリックしてSNS投稿画面に戻る。

この循環がプロダクトの差別化の核心です。

説明文を読まなくても、操作だけで仕組みが理解できるUXを目指してください。

## 5. インタラクションとモックデータ

**見た目だけのボタンを極力作らないでください。**

最低限、以下は正常動作させてください。

- 投稿作成
- 画像添付・プレビュー
- いいねの切り替え
- コメント投稿
- リポスト・引用投稿
- 投稿保存
- フォロー
- フィード検索
- レポジトリ検索・フィルター
- 画面間ナビゲーション
- AXパッケージ詳細表示
- QommonsAI差分確認デモ
- 改善案の投稿

データはローカル状態・localStorageなどで管理して構いません。実際のバックエンドは不要です。

最初から10件程度の自然な投稿を表示してください。

投稿テーマ：
- 給付金申請の審査
- 議案答弁書の作成
- 例規検索
- 庁内問い合わせ対応
- 補助金制度の調査
- 自治体広報
- 窓口業務の効率化

投稿者には異なる架空自治体・部署・プロフィール画像を用意し、同じカードが機械的に並ぶ印象を避けてください。

Polimill公式投稿には、QommonsAIの活用Tipsやイベント案内を含めてください。

デモデータは架空とし、実在自治体の成果・実績と誤認される表現は避けてください。

全国行政AXレポジトリは添付資料に記載された2027年4月公開予定の構想として扱い、すでに正式運用されているかのようには表示しないでください。

## 7. 開発プロセスと品質保証

1. GitHubリポジトリを確認する。
2. 添付のUI画像・Polimillロゴ・AXレポジトリ資料を確認する。
3. 画面全体のデザインシステムとコンポーネントを設計する。
4. 最優先でホームフィードを高品質に作り込む。
5. レポジトリ画面・詳細画面・プロフィールを構築する。
6. SNSとAXレポジトリとQommonsAIの遷移を接続する。
7. インタラクションを実装する。
8. ブラウザで実際に操作し、UIを確認・修正する。
9. ビルド・動作確認を実施する。
10. GitHubへ反映できる状態にする。

### 品質基準

- PCブラウザで実在サービスらしいUI品質
- 日本語テキストの自然さ
- レイアウト崩れがない
- ボタン・ナビゲーションが適切に機能する
- デモ中に行き止まりにならない
- コンソールエラーがない
- 主要な操作が一連のシナリオとして成立する
- スマートフォンでも利用可能
- ローディング・空状態・ホバーなどの細部まで丁寧に設計する

実装後は可能な限りブラウザでスクリーンショットを撮影し、添付LinkedIn画像の情報密度・余白・カード構成・完成度と比較して改善してください。

単にコードが動く状態ではなく、視覚面も含めて完成させてください。

## 9. 完成の定義

**社長が90秒のデモを見て、次のことを直感的に理解できれば成功です。**

1. Qommons INは全国の自治体職員をつなぐ、LinkedIn型のコミュニティである。
2. 職員の投稿・議論が、全国行政AXレポジトリの業務の型と接続されている。
3. QommonsAIによって、その知識を他自治体の実務でも活用できる。
4. 自治体間で知恵が蓄積・再利用され、全国的な行政業務の改善につながる。

**UI/UXのリアリティが最優先です。**

機能を大量に実装するよりも、ホームフィードの完成度、投稿からレポジトリへの接続、QommonsAIによる実務活用の3つを高い品質で実現してください。

まずは既存の商用SNSと同じように感じられる、洗練された行政職員向けWebアプリとして仕上げてください。
